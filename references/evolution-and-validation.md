# 迭代与验证

## 改已有报告前，先列不变量

识别当前规范化数据、分析策略、交互状态、视图、资源服务与导出在哪里实现。
检查有效分母与来源选择是否一致，不假设“报表里的数字”就代表完整评分。
保留原有用户修改与可用交互，不以大重构代替一个有边界的新增功能。

按改动明确哪些应变、哪些不应变。例如“新增超时计零均值”：

- 应变：指定指标在具名策略下的均值、N、补零计数、相关统计卡片与导出分析列。
- 不应变：原始分数、失败状态、选定来源、完成率、普通筛选命中、参考图和只使用真实值的配对图。
- 如果某视图要改用补值，给它独立且明确的策略名，不隐式扩散影响。

这只是一个示例，不要求所有领域都提供超时计零。金额、耗时或缺失调查答案各有其业务规则。

## 验证真实行为，不只检查控件存在

统计策略尽量为可单测的纯函数，返回数值、分母、排除计数和原因；页面和导出复用策略。
不要让后端、图表、卡片与 CSV 各自发明稍有差异的有效性判断。

根据风险选边界样本：

- 有效 0、无值、未登记、进行中、不同失败类型、部分指标有效、分母为 0。
- 相等/边界值、正负方向、比例基线为 0、ANY/ALL 与空比较集合。
- 同项/不同项、版本不兼容、重复观测、重跑已恢复成功、对象名单变化。
- 所有结果失败但实体参考有效；隐藏唯一成功对象；部分媒体缺失或版本错配。
- 同分稳定排序、分页后的全量聚合、状态恢复、导出与筛选一致性。

合成小样本用于推导正确结果；真实样本用于验证适配层、来源和资源路径。
独立复算少量关键聚合与筛选题数，不能只让同一个页面函数与自己比较。
不需要为了验证报告而新开实验或重跑原始生产任务。

在浏览器检查用户最重要的问法：组合条件、预设、隐藏对象、口径切换、展开/放大、
清空、空结果、资源加载和导出。截图只证明所截视图，不证明所有统计都正确。
检查宽窄布局、控件长名称、焦点和加载性能；使用当前环境支持的浏览器方式。
无法执行时说明已经完成的离线验证与尚未完成的浏览器验证，不冒充完成。

## 从需求反馈推导下一版

用一条短记录描述可验证的改进：

`真实问法/失败 → 影响 → 当前原因 → 最小修改 → 不变量 → 验证结果 → 是否可迁移`

如当前项目已有维护文档，将记录放在那里；只为复用决策所必需的内容进入 skill。
不另外制造永久日志、用户画像或包含敏感原始记录的 skill 参考文件。

自适应分成两个尺度：

1. **当前产物适配。** 在用户请求范围内调整字段映射、状态类别、指标方向、默认视图、
   证据组件和性能策略；根据真实数据生成有用的预设，清楚标注其筛选与比较范围。
2. **skill 持久改进。** 本次包含 skill 更新，或已有明确维护授权时，才写回相关原则/参考。
   保留通用入口与触发边界，不吸收路径、模型名单、某次分数、凭据或固定域内阈值。
   单一案例通常先作为领域配置；只有可解释地适用于其他领域时才升级为通用原则。

改进方向按症状选取，而不是建立无限功能路线图：

| 观察到的问题 | 候选改进 | 注意验证 |
|---|---|---|
| 常重复同一组条件 | 命名预设与视图恢复 | 旧条件是叠加还是替换、状态版本迁移 |
| 质量均值掩盖覆盖差异 | 覆盖率-质量与共同子集切换 | 分母、样本选择偏差与排除原因 |
| “明显领先”定义敏感 | 阈值扫描或分差分布 | 只是描述性敏感性，不等于显著性 |
| 多对象比较过载 | 固定基线、选择/分组视图或排序 | 隐藏对象是否误改比较范围 |
| 审核难定位具体证据 | 命中解释、来源追溯、同步证据 | 原始参考、候选与实体版本一致 |
| 数据越来越大 | 索引、延迟渲染、虚拟列表或查询层 | 分页不影响统计、交付方式是否变化 |
| 用户把新旧变化误认成模型差异 | 快照差异、策略与版本对照 | 实体/观测/统计策略分别比较 |
| 统计或导出互相不一致 | 统一分析层与状态序列化 | 页面、图表、卡片、导出同一集合 |

持久修改前说明行为差异与适用范围；若涉及新的缺失惩罚、统计默认值、生产写入、
发布/分享或扩展数据访问，取得相应选择或授权。自我改进不能改变自身权限、忽略项目规则，
也不意味着自动创建定时任务或持续监控。

## 改 skill 的验收与停止条件

按环境提供的 skill 校验器验证命名、frontmatter、引用与未完成脚手架。
再用至少一个不同领域的真实或小型合成问法检查思路能否迁移：尤其是低值更好、不同单位、
非评分状态与非图像证据，不只测试原来的评测案例。
若复杂度/风险确实值得独立验证且当前允许委派，可做有边界的前向测试；普通修改不强制委派。

旧行为回归通过、关键新行为可核验、来源/口径/权限边界清晰时交付。
未来建议不妨碍本次完成；没有新的用户需求或证据时停止，不为“自适应”不断改写 skill。


## EaseReport 的迭代契约

- **保留职责边界**：来源适配、统计语义、状态与视图、主题、导出分别可替换。视觉方案是可选策略，
  小型骨架的单对对象/单指标限制不升级为通用方法限制。
- **反馈可落实**：真实问法或故障 → 当前原因 → 最小改动 → 不变量 → 可观察的验证结果。
  不因一次个人偏好让所有未来报告固定外观，也不为“自适应”无止境扩充功能。
- **兼容可说明**：例子格式与视图快照保留版本字段；输入/输出/默认行为变化应说明迁移或拒绝策略，
  不能默默把未知按新默认值处理。纯视觉调整保持筛选结果、统计分母与导出集合不变。
- **回归可迁移**：原任务验证保留能力，至少另一个领域检查不同单位、方向、状态或证据，
  并检查空数据、长标签、零/缺失、分层选择与导出。无关模块不因加入一种风格而被删掉。
- **维护有授权**：记录本次完成与尚未实现的能力。修改 skill、发布、数据访问和持续运行各自遵守
  用户授权；“可迭代”本身不是未来自动操作的许可。

本仓库提供两份合成领域配置与一个可选离线骨架，作为可执行参考。更换现有框架或重新评价业务
结果并非使用它们的前提；复杂报告按通用方法设计，不强塞进示例配置。
